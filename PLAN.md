## Intent (verbatim)

> Mouthy is a free, open-source, offline-first desktop text-to-speech app for macOS (Windows/Linux later). Core loop: user highlights text in any app → presses a global hotkey → the text is read aloud by a local neural TTS voice → pressing the hotkey again stops playback. It is the inverse of Handy. We are forking Handy and inverting its I/O path rather than starting from scratch.
>
> Step 0 … 5. Write the module map and a phased plan to PLAN.md, and ask me to confirm it before Phase 1. Keep CLAUDE.md but rewrite it for Mouthy as the first commit after the plan is agreed.
>
> ## Hard constraints
>
> - **Rebrand completely and early.** Handy's name, logo, icon, and brand assets are NOT open source. Replace every occurrence: app name, bundle identifier (use `com.azizi.mouthy`), tauri.conf.json product name/identifier/window titles, icons (generate simple placeholder icons for now), tray tooltip, README, website links, release notes, sponsor images (delete), Discord links (delete), updater endpoint and pubkey (remove the updater entirely for now; we'll add our own later), app-data directory name. Add an attribution line in README and LICENSE noting Mouthy is derived from Handy (MIT, cjpais) and is not affiliated or endorsed.
> - **Keep Handy's architecture and conventions.** Tauri 2, Rust backend, React + TypeScript + Tailwind frontend, bun, the existing settings and command patterns, the existing lint/format config. Don't introduce new frameworks. Match the existing code style exactly.
> - **Delete, don't disable.** Remove STT code paths outright (VAD, Whisper/transcribe-cpp, Parakeet/transcribe-rs, microphone capture, dictionary/post-processing, transcript history) and their Cargo/package dependencies, so the binary and build get smaller. Keep a clean git history: one commit per logical removal.
> - **macOS first.** Everything must work on an Apple-Silicon Mac. Leave Windows/Linux code paths compiling where cheap, but don't spend effort on them.
> - **Offline by default is the end state** (Phase 2). Phase 1 may depend on a local HTTP server.
> - Ask before adding any dependency not already in the repo.
>
> ## Phase 1 — app shell with an external TTS backend
>
> Goal: Mouthy.app that fully works against a locally running OpenAI-compatible TTS server (I run Kokoro-FastAPI at http://127.0.0.1:8880, endpoint POST /v1/audio/speech, voice `bm_lewis`).
>
> Behaviour:
>
> 1. Global hotkey (default ⌥⎋ / Alt+Escape — same as macOS "Speak selection"; configurable in Settings like Handy's shortcuts). On press:
>    - If currently speaking → stop immediately.
>    - Else capture the current selection: save the clipboard, send ⌘C via the existing enigo path, poll the clipboard for a change (≤200 ms), read the text, restore the clipboard. If nothing was selected, show a brief overlay notice and do nothing.
> 2. Light text normalisation before synthesis (strip URLs → "link", collapse whitespace, drop markdown symbols, \* # ` > etc.). Keep this in one small, tested Rust function.
> 3. Split the text into sentences, synthesise sentence-by-sentence, and start playback as soon as the first sentence's audio is ready while the rest is still synthesising (bounded channel/queue). Playback via the audio-output path already present (cpal/rodio — use whatever Handy already uses for audio feedback; don't add a second audio stack).
> 4. Overlay (reuse Handy's recording overlay) shows a "speaking" state while audio plays; hides on stop/finish.
> 5. Settings UI: hotkey, backend URL, voice (free-text for now, dropdown populated from the server's /v1/audio/voices if it exists), speed (0.5–2.0), volume, "launch at login", "start hidden", overlay position. Remove all STT settings.
> 6. Tray menu: Speak selection / Stop / Settings / Quit.
> 7. CLI flags via the single-instance plugin, mirroring Handy's: `--speak-selection`, `--stop`, `--start-hidden`, `--no-tray`.
> 8. Graceful failure: if the backend is unreachable, overlay shows an error and a Settings link; never crash.
>
> Definition of done for Phase 1: fresh clone → build → launch → grant Accessibility permission → highlight text in Safari and in VS Code → ⌥⎋ reads it in Lewis's voice → ⌥⎋ stops it. `cargo test` and `bun run lint` are clean. README documents setup.
>
> ## Phase 2 — in-process Kokoro (offline)
>
> Replace the HTTP backend with Kokoro-82M running inside the Rust process via ONNX Runtime (`ort` crate), keeping the HTTP backend as a selectable fallback. Reuse Handy's model-manager pattern: Settings → Models page, download the ONNX model + voices file to the app-data `models/` dir with progress, verify checksum, select active model. Phonemisation is the hard part: evaluate (a) an existing Rust Kokoro crate (e.g. `kokoros` / `kokoro-tts`) vs (b) `ort` + our own G2P via espeak-ng bindings. Write up the trade-offs (binary size, licence, maintenance, macOS build complexity, CoreML/Metal EP availability) in PLAN.md and let me choose before implementing. Target: first audio within ~300 ms of the hotkey for a sentence on an M-series Mac.
>
> ## Phase 3 — polish (only after I say so)
>
> Voice picker with per-voice preview, voice blending, a signed release build via `tauri build`, a Homebrew cask formula in a tap, proper icon, auto-update.

### (c) Hotkey → action path, and its inversion

Handy: key event → `handle_shortcut_event` → `TranscriptionCoordinator` (debounce, PTT/hold/toggle) → `TranscribeAction::start` (model, mic, VAD, overlay, tray) → `stop` → transcribe → post-process → `clipboard::paste` (save → write → ⌘V → delay → restore).
Mouthy (D10): Carbon hotkey on main thread → `handle_shortcut_event` → `ACTION_MAP["speak"]` → `SpeakAction::start` (release ignored): lock `TtsState`; if a session is current → set its stop flag, hide overlay, tray Idle; else set `Capturing`, `clipboard::capture_selection` inline (D12), normalize + split, create `Session{generation, stop}`, spawn synth thread + playback thread, overlay "speaking", tray Speaking. `--speak-selection`/`--stop`/SIGUSR2/SIGUSR1 and the tray items call the same two entry points via `run_on_main_thread` (fire-and-forget).

## Research Notes

- **rodio 0.23** (registry source): `Sink` is now `Player` (`append`, `stop`, `clear`, `empty`, `len`, `set_volume`, `sleep_until_end`; `append` after `stop` resumes; stop is immediate, 5 ms periodic). `Player::connect_new(&mixer)`. `SamplesBuffer::new(NonZero<u16>, NonZero<u32>, impl Into<Vec<f32>>)` — **f32 only**. `wav` feature = symphonia. Mixer resamples 24 kHz mono. `MixerDeviceSink` must live on the playback thread.
- **Kokoro-FastAPI live probe:** `GET /v1/audio/voices` → `{"voices":[{"id":"af_alloy","name":…}]}`. `POST /v1/audio/speech`: `input`, `voice`, `response_format` ∈ mp3|opus|aac|flac|wav|pcm, `speed` 0.25–4.0, `stream` (default true), `volume_multiplier`, `lang_code`. Two-sentence WAV 0.57 s (TTFB 21 ms); one sentence PCM 0.27 s. **WAV headers carry RIFF/data size 0xFFFFFFFF even with `stream:false`**; `pcm` = raw s16le mono 24 kHz, no header → D2.

## Decisions (defaults confirmed by H1; review ids in brackets)

- **D1 Toggle only.** Coordinator + `shortcut_activation`/`hold_threshold_ms` deleted; `SpeakAction` ignores release.
- **D2 PCM, not WAV** [A1]: `response_format:"pcm"`, `stream:false`, one request per sentence, const `24_000` Hz in `tts/http.rs`. Server WAV headers are placeholders; PCM needs no decoder and is faster to first byte.
