# Plan review — round 1 findings (correctness 60%, integration 85%, simplicity 62%)

## Correctness (C)
- C-M1 One shared stop flag across sessions + rodio `Player::append` after `stop` resumes playback (player.rs:104-110). Stop can let a buffered sentence play; fast re-press lets session A's late HTTP result play over session B; A's Finished hides B's overlay. Fix: per-session stop token/generation id in `TtsState` under a Mutex; Finished/Error only mutate shared state if session id is current; playback thread checks flag after every recv and before every append.
- C-M2 Stop design can't work with described ownership: receiver lives on playback thread, so stopper can't drop it; `Player::append` never blocks so `sync_channel(2)` never fills and synth runs to end of text; `SyncSender::send` inside an async task blocks a tokio worker. Fix: Player stays on playback thread only; loop on `rx.recv_timeout(20ms)` checking session flag; only recv next chunk when `player.len() < 2` (real read-ahead bound); on stop `player.stop()` and return; wait for end with `while !player.empty() && !stopped {sleep 20ms}`; run synthesis on a plain thread with `tauri::async_runtime::block_on` per request, checking the flag before each request.
- C-M3 ⌘C injection must run on main thread: input.rs:75-77 (TIS APIs main-thread only); handy-keys thread (handy_keys.rs:110-134) and signal thread call the action off-main. Fix: T2 wraps `capture_selection` in `app.run_on_main_thread` with result over a channel (runs inline if already on main: tauri-runtime-wry lib.rs:239-248).
- C-M4 R2/R3 don't compile as ordered: `audio_toolkit/audio/utils.rs::read_wav_samples` used by lib.rs:526 (R3), engine_supervisor/supervisor.rs:1493 test (R3), commands/history.rs:77 (R5). commands/history.rs:2-4,67 takes `State<Arc<TranscriptionManager>>` and calls `actions::process_transcription_output` (R1 must keep that helper or delete the command earlier). `tokio::task::spawn_blocking` used by kept commands/audio.rs:255; llm_client.rs:534-648 tests use `#[tokio::test]` (R4). Fix: delete `retry_history_entry_transcription` + frontend caller in R1/R2; keep audio/utils.rs + hound until R3; switch commands/audio.rs to `tauri::async_runtime::spawn_blocking` in R3; keep tokio dev-dep until R4.
- C-M5 bindings.ts is exported at app launch in debug (lib.rs:778-784), NOT on `cargo build`. Per-stage check is blind to stale bindings. Fix: per-stage step: run debug binary briefly (export runs before single-instance at lib.rs:856) then `git diff --stat src/bindings.ts`; commit bindings with each stage.
- C-S1 `SamplesBuffer::new(NonZero<u16>, NonZero<u32>, Into<Vec<f32>>)` — Vec<i16> won't compile; convert `s as f32 / 32768.0` (else clipped noise).
- C-S2 `async fn` in trait not dyn-safe (see also S-M1).

- C-sus ⌥ still held during ⌘C — enigo sets flags explicitly so should be fine; add to manual test. Tauri global-shortcut path may send repeated Pressed events once the coordinator's 30ms debounce is gone (handy-keys suppresses repeats itself).
