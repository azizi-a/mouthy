## Verdict

High-load bearing area with extensive dependencies on STT infrastructure. Handy is a tightly integrated speech-to-text application built around microphone capture, VAD filtering, transcription processing, and text pasting. The inversion to TTS (text → clipboard capture → audio synthesis → playback) requires removal of ~40% of the codebase by LOC and systematic rewiring of the action flow.

## Hotkey → Action → Paste Path: INVERSION REQUIRED

### Current STT Flow (Hold-to-record + Toggle modes)

1. **Hotkey Press (rdev / global-shortcut)**
   - `shortcut/handler.rs` receives event
   - Determines mode: PushToTalk (hold), Toggle (tap), HoldOrToggle (smart)

2. **Action Start**
   - `actions.rs::TranscribeAction::start()` called
   - Plays "recording start" sound via `audio_feedback.rs`
   - Shows recording overlay (pill/minimal state)
   - Calls `AudioRecordingManager::start_recording()` → `handy_recorder` opens mic
   - Audio fed through VAD (Silero/Earshot) filters silence
   - Streaming inference in `managers/transcription.rs` sends live text to overlay

3. **Hotkey Release (or timeout)**
   - `actions.rs::TranscribeAction::stop()` called
   - VAD stops feeding frames, model finalizes transcription
   - Text post-processed (filler words, dictionary replacements, LLM polish)
   - Played sound: "recording stop"
   - Shown state: "Processing" overlay

4. **Paste Output**
   - `clipboard.rs::paste_via_clipboard()` saves old clipboard
   - Writes transcription to clipboard
   - Sends ⌘V (Ctrl+V on Windows/Linux)
   - Waits (paste_delay_after_ms, default 100)
   - Restores old clipboard OR uses `paste_tx/` receipt mechanism (macOS/Windows beta)

### Required Changes for TTS Inversion

| Phase | Current (STT) | Inverted (TTS) |
|-------|---------------|----------------|
| **Hotkey press** | Start recording | Read clipboard (⌘C), or show text input UI |
| **Processing** | Transcribe via Whisper/Parakeet | Send text to TTS backend (local/remote API) |
| **Output** | Paste text | Play audio stream (WAV/MP3) to speakers |
| **Hotkey release** | Stop recording | Pause/stop playback |
| **Second press** (during operation) | Cancel recording | Stop playback, cancel TTS |

### Specific Code Paths to Modify

1. **`src-tauri/src/actions.rs`**
   - Delete `TranscribeAction` struct
   - Create `TextToSpeechAction` struct with `post_process: bool` (?)
   - `start()`: Call `clipboard.read_selected_text()` or show UI for text input
   - `stop()`: Stop audio playback

2. **`src-tauri/src/clipboard.rs`**
   - Add `pub fn read_text_from_clipboard()` (inverse of current write)
   - Keep paste functions (may be used for alternative input methods)

3. **New module: `src-tauri/src/tts_backend/`** (create)
   - Abstract trait `TTSBackend`
   - Impls: `ElevenLabsBackend`, `LocalEdgeTTSBackend`, `OpenAIBackend`, etc.
   - Stream WAV chunks back to playback
   - Handle language/voice selection from settings

4. **New module: `src-tauri/src/audio_output/`** (create)
   - Stream WAV/MP3 chunks to speakers via `rodio` (or `cpal` for lower latency)
   - Pause/resume control
   - Volume control

5. **`src-tauri/src/managers/`** (modify/remove)
   - Remove `transcription.rs` (entire 2500-line module)
   - Remove `model.rs` (entire 3500-line module) — no TTS models to manage
   - Keep `audio.rs` as template, create `playback_manager.rs` instead
   - Remove `history.rs` or adapt to store TTS synthesis requests

6. **`src-tauri/src/overlay.rs` + `src/overlay/`**
   - Rename "recording" states to "playing" or "synthesizing"
   - Hide microphone-related UI
   - Show playback progress bar + pause/resume buttons

## Audio Feedback & Playback Stack

### Current Implementation (`audio_feedback.rs`)

**Crate:** `rodio = "0.23.0"` (with features: playback, wav, flac, mp3, vorbis)

**API:**
```rust
fn play_sound_at_path(path: &Path, device: Option<String>, volume: f32) 
  → rodio::DeviceSinkBuilder 
  → File::open(path) → BufReader
  → rodio::play(mixer, source) 
  → source.set_volume(volume)
  → source.sleep_until_end()
```

**For TTS playback:**
- **Streaming use case:** Synthesizer produces chunks (PCM frames or WAV segments)
- **Current design:** Blocks on `sleep_until_end()` → suitable for TTS (play to completion)
- **Adaptation needed:**
  - Accept `Vec<u8>` (WAV data) or `io::Read` stream instead of file path
  - Use `rodio::Sink` for pause/resume capability
  - `sink.pause()` / `sink.play()` for playback control

**Alternative consideration:**
- `cpal = 0.13+` (from `rodio` dependency tree) — Lower-level audio API
- Direct buffer writing if latency/real-time synthesis matters

### HTTP Client for TTS Calls

**Cargo dep:** `reqwest = "0.12"` (with features: json, stream, gzip, brotli, deflate)

**Current usage:**
- `llm_client.rs` — LLM post-processing API calls (OpenAI, local Ollama, etc.)
- For TTS, reuse same infrastructure:
  - ElevenLabs API
  - OpenAI text-to-speech endpoint
  - Local TTS server (edge-tts, etc.)

**Pattern to follow:**
```rust
reqwest::Client::new()
  .post(api_url)
  .json(&TextToSpeechRequest { text, voice, ... })
  .send()
  .await?
  .bytes_stream()  // ← stream chunks
  .take(chunk_rx)  // Stop if cancelled
```

- SIGUSR1 → toggle with post-processing (macOS only)
- Reason: WebKitGTK uses SIGUSR1 internally on Linux (issue #1660)
- For TTS: Keep signal routing, adapt binding IDs

## HTTP Client Dependency

**Crate:** `reqwest = "0.12"` with features: json, stream, gzip, brotli, deflate

**Current usage:** `llm_client.rs` (LLM API calls for post-processing)

**For TTS:** Reuse for:
- ElevenLabs API (GET/POST with streaming response)
- OpenAI text-to-speech
- Local TTS server integration

**Streaming pattern in Handy:**
```rust
let response = client.post(url).json(&body).send().await?;
let mut stream = response.bytes_stream();
while let Some(chunk) = stream.next().await {
    // Process chunk
}
```
