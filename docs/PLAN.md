## Intent (verbatim)

> Mouthy is a free, open-source, offline-first desktop text-to-speech app for macOS (Windows/Linux later). Core loop: user highlights text in any app → presses a global hotkey → the text is read aloud by a local neural TTS voice → pressing the hotkey again stops playback. It is the inverse of Handy. We are forking Handy and inverting its I/O path rather than starting from scratch.
>
> Step 0 … 5. Write the module map and a phased plan to PLAN.md, and ask me to confirm it before Phase 1. Keep CLAUDE.md but rewrite it for Mouthy as the first commit after the plan is agreed.
>
> ## Hard constraints
>
> - **Rebrand completely and early.** Handy's name, logo, icon, and brand assets are NOT open source. Replace every occurrence: app name, bundle identifier (use `com.azizi.mouthy`), tauri.conf.json product name/identifier/window titles, icons (generate simple placeholder icons for now), tray tooltip, README, website links, release notes, sponsor images (delete), Discord links (delete), updater endpoint and pubkey (remove the updater entirely for now; we'll add our own later), app-data directory name. Add an attribution line in README and LICENSE noting Mouthy is derived from Handy (MIT, cjpais) and is not affiliated or endorsed.
> - **Keep Handy's architecture and conventions.** Tauri 2, Rust backend, React + TypeScript + Tailwind frontend, bun, the existing settings and command patterns, the existing lint/format config. Don't introduce new frameworks. Match the existing code style exactly.
> - **Delete, don't disable.** Remove STT code paths outright (VAD, Whisper/transcribe-cpp, Parakeet/transcribe-rs, microphone capture, dictionary/post-processing, transcript history) and their Cargo/package dependencies, so the binary and build get smaller. Keep a clean git history: one commit per logical removal.
> - **macOS first.** Everything must work on an Apple-Silicon Mac. Leave Windows/Linux code paths compiling where cheap, but don't spend effort on them.
> - **Offline by default is the end state** (Phase 2). Phase 1 may depend on a local HTTP server.
> - Ask before adding any dependency not already in the repo.
>
> ## Phase 1 — app shell with an external TTS backend
>
> Goal: Mouthy.app that fully works against a locally running OpenAI-compatible TTS server (I run Kokoro-FastAPI at http://127.0.0.1:8880, endpoint POST /v1/audio/speech, voice `bm_lewis`).
>
> Behaviour:
>
> 1. Global hotkey (default ⌥⎋ / Alt+Escape — same as macOS "Speak selection"; configurable in Settings like Handy's shortcuts). On press:
>    - If currently speaking → stop immediately.
>    - Else capture the current selection: save the clipboard, send ⌘C via the existing enigo path, poll the clipboard for a change (≤200 ms), read the text, restore the clipboard. If nothing was selected, show a brief overlay notice and do nothing.
> 2. Light text normalisation before synthesis (strip URLs → "link", collapse whitespace, drop markdown symbols, \* # ` > etc.). Keep this in one small, tested Rust function.
> 3. Split the text into sentences, synthesise sentence-by-sentence, and start playback as soon as the first sentence's audio is ready while the rest is still synthesising (bounded channel/queue). Playback via the audio-output path already present (cpal/rodio — use whatever Handy already uses for audio feedback; don't add a second audio stack).
> 4. Overlay (reuse Handy's recording overlay) shows a "speaking" state while audio plays; hides on stop/finish.
> 5. Settings UI: hotkey, backend URL, voice (free-text for now, dropdown populated from the server's /v1/audio/voices if it exists), speed (0.5–2.0), volume, "launch at login", "start hidden", overlay position. Remove all STT settings.
> 6. Tray menu: Speak selection / Stop / Settings / Quit.
> 7. CLI flags via the single-instance plugin, mirroring Handy's: `--speak-selection`, `--stop`, `--start-hidden`, `--no-tray`.
> 8. Graceful failure: if the backend is unreachable, overlay shows an error and a Settings link; never crash.
>
> Definition of done for Phase 1: fresh clone → build → launch → grant Accessibility permission → highlight text in Safari and in VS Code → ⌥⎋ reads it in Lewis's voice → ⌥⎋ stops it. `cargo test` and `bun run lint` are clean. README documents setup.
>
> ## Phase 2 — in-process Kokoro (offline)
>
> Replace the HTTP backend with Kokoro-82M running inside the Rust process via ONNX Runtime (`ort` crate), keeping the HTTP backend as a selectable fallback. Reuse Handy's model-manager pattern: Settings → Models page, download the ONNX model + voices file to the app-data `models/` dir with progress, verify checksum, select active model. Phonemisation is the hard part: evaluate (a) an existing Rust Kokoro crate (e.g. `kokoros` / `kokoro-tts`) vs (b) `ort` + our own G2P via espeak-ng bindings. Write up the trade-offs (binary size, licence, maintenance, macOS build complexity, CoreML/Metal EP availability) in PLAN.md and let me choose before implementing. Target: first audio within ~300 ms of the hotkey for a sentence on an M-series Mac.
>
> ## Phase 3 — polish (only after I say so)
>
> Voice picker with per-voice preview, voice blending, a signed release build via `tauri build`, a Homebrew cask formula in a tap, proper icon, auto-update.
>
> ## Working style
>
> - Work in small commits with conventional-commit messages. Run the app and actually test the hotkey loop yourself where you can; tell me exactly what you could not verify.
> - Don't ask me questions you can answer by reading the repo. Do ask before architectural choices not covered here.
> - Keep a running CHANGELOG.md.

### (c) Hotkey → action path, and its inversion

Handy: key event → `handle_shortcut_event` → `TranscriptionCoordinator` (debounce, PTT/hold/toggle) → `TranscribeAction::start` (model, mic, VAD, overlay, tray) → `stop` → transcribe → post-process → `clipboard::paste` (save → write → ⌘V → delay → restore).
Mouthy (D10): Carbon hotkey on main thread → `handle_shortcut_event` → `ACTION_MAP["speak"]` → `SpeakAction::start` (release ignored): lock `TtsState`; if a session is current → set its stop flag, hide overlay, tray Idle; else set `Capturing`, `clipboard::capture_selection` inline (D12), normalize + split, create `Session{generation, stop}`, spawn synth thread + playback thread, overlay "speaking", tray Speaking. `--speak-selection`/`--stop`/SIGUSR2/SIGUSR1 and the tray items call the same two entry points via `run_on_main_thread` (fire-and-forget).

## Research Notes

- **rodio 0.23** (registry source): `Sink` is now `Player` (`append`, `stop`, `clear`, `empty`, `len`, `set_volume`, `sleep_until_end`; `append` after `stop` resumes; stop is immediate, 5 ms periodic). `Player::connect_new(&mixer)`. `SamplesBuffer::new(NonZero<u16>, NonZero<u32>, impl Into<Vec<f32>>)` — **f32 only**. `wav` feature = symphonia. Mixer resamples 24 kHz mono. `MixerDeviceSink` must live on the playback thread.

## Phase 2 — P2.1 Phonemisation trade-off study

Written 2026-10-13 from web research (URLs inline) plus a timing spike run in the scratchpad (`kspike/`, Python `onnxruntime` 1.31.0 + `kokoro-onnx` 0.6.1, Homebrew espeak-ng 1.52, this M4 Pro 10P+4E). No source file changed; no dependency added.

### Facts that frame every option

- **`ort`** ([pykeio/ort](https://github.com/pykeio/ort)): no 2.0 final; latest `2.0.0-rc.14` (2026-10-12, ONNX Runtime 1.31.0), MIT/Apache-2.0. Every rc broke the API (rc.14: `ort::init().build()` env is mandatory; `SessionBuilder` defaults to `AutoDevicePolicy::MaxEfficiency`, which silently routes to CoreML on macOS and breaks Kokoro's zero-size slices — [#662](https://github.com/pykeio/ort/issues/662); use `PreferCPU`). Pin `=2.0.0-rc.14`. Default `download-binaries` fetches a 9.7 MB archive from pyke's CDN at build time → static `libonnxruntime.a` (83 MB, CoreML built in); **+19 MB on a stripped arm64 release binary** (measured by the research agent; Mouthy.app is 9.6 MB today). Only `aarch64-apple-darwin` is prebuilt — no x86_64/universal without a source build or `load-dynamic` (`ORT_DYLIB_PATH`, Microsoft dylib 44.8 MB). [Linking docs](https://ort.pyke.io/setup/linking).
- **CoreML/Metal:** ONNX Runtime has no Metal/MPS EP; WebGPU EP (Dawn→Metal) is marked experimental. The CoreML EP accepts only ~1050/2478 Kokoro nodes (STFT, LSTM, zero-size slices, dynamic sequence length) — [kokoro-onnx #16](https://github.com/thewh1teagle/kokoro-onnx/issues/16), [#56](https://github.com/thewh1teagle/kokoro-onnx/issues/56). **Measured here:** CoreML EP was equal or slower than CPU and added 3–4 s session-load time. Treat Phase 2 as CPU-only; CoreML gains need a native Core ML conversion (out of scope).
- **Model files** (Apache-2.0): [onnx-community/Kokoro-82M-v1.0-ONNX](https://huggingface.co/onnx-community/Kokoro-82M-v1.0-ONNX) `onnx/model.onnx` 325,532,232 B (fp32), `model_fp16.onnx` 163,234,740, `model_quantized.onnx` 92,361,116 (int8); inputs `input_ids` i64 [1,n], `style` f32 [1,256], `speed` f32 [1]; output `waveform` 24 kHz; ≤510 tokens. Voices: `voices/<id>.bin`, raw little-endian f32, 522,240 B each, reshape (510,1,256), row = token count — **no npz reader needed**. sha256 for P2.3 = `lfs.oid` from `GET https://huggingface.co/api/models/onnx-community/Kokoro-82M-v1.0-ONNX/tree/main/onnx` (verified). `bm_lewis` exists (hexgrad grade D+; `bf_emma` B- is the best British voice). No Kokoro English release after v1.0 (Jan 2025).
- **espeak-ng is GPL-3.0-or-later.** FSF reads static, dynamic and dlopen linking all as a combined work ([GPL FAQ](https://www.gnu.org/licenses/gpl-faq.en.html#GPLStaticVsDynamic)); a subprocess exchanging plain text over argv/stdout is "mere aggregation". Every Rust binding (`espeak-rs`/`espeak-rs-sys` 0.2.0 vendors + statically compiles espeak-ng via cmake; `espeakng-sys` 0.3.0 links a system lib with no pkg-config) is MIT-labelled but inherits GPL. Precedent: Piper moved to `piper1-gpl` once it embedded espeak-ng; sherpa-onnx is removing espeak-ng for 2.0 as "incompatible with Apache-2.0" ([#3731](https://github.com/k2-fsa/sherpa-onnx/issues/3731)). Homebrew `espeak-ng` 1.52.0 is installed on this machine (`/opt/homebrew/lib/libespeak-ng.dylib`, data `/opt/homebrew/share/espeak-ng-data`).
- **Pure-Rust G2P exists and is MIT:** [`misaki-rs`](https://github.com/MicheleYin/misaki-rs) 0.6.0 (2026-09-02, 77k downloads) ports hexgrad's misaki (Apache-2.0): embedded US+GB gold/silver lexicons (~197k GB forms), perceptron POS tagger, num2words; `default-features = false` drops `espeak-rs`, and OOV words are then spelled letter-by-letter. [`loqui-g2p`](https://github.com/Awakened-Labs/loqui) 0.3.0 (2026-10-04, 1 contributor, 273 downloads) is the same idea plus an embedded pure-Rust neural OOV fallback and `Dialect::for_kokoro_voice("bm_…")`. Both crates are ~9 MB (lexicons).
- **Rust Kokoro crates** all wrap `ort` and differ only in G2P: Kokoros (git-only, Apache-2.0, `espeak-rs` static GPL, 16 deps incl. tokio/reqwest/mp3lame, unpinned `ort` that drifted to rc.14 and broke, [#121](https://github.com/lucasjinreal/Kokoros/issues/121)); kokorox (now GPL-3.0); kokoro-tts 0.3.3 (US dict only, hard-codes CUDA EP); kokoro-en 0.1.5 (misaki-rs + ort coreml, 12 deps, GB via a global env var); loqui-kokoro 0.3.0 (4 deps, `ort =rc.13`, no streaming, returns whole `Vec<f32>`); kokoro-micro 1.3.0 (pure-Rust lexicon, open macOS teardown crash). ### Latency vs the ~300 ms target (measured on this M4 Pro, CPU EP, warm session)

| Model                               | 3 words / 18 ph | 5 words / 33 ph | 14 words / 81 ph | 28 words / 190 ph |
| ----------------------------------- | --------------- | --------------- | ---------------- | ----------------- |

Session load: fp32 0.58 s, int8 0.41 s (do once at model select, not per hotkey). G2P: Homebrew espeak-ng in-process ≈0 ms after a 0.5 s first-call init (CLI spawn 30 ms wall); `misaki-rs` lexicon lookup is unmeasured but is hash lookups, expect <2 ms. Playback start via rodio after `append` is tens of ms. Phase 1 capture (⌘C + clipboard poll) adds ~50–200 ms before synthesis begins. **Conclusion:** a short first sentence meets ~300 ms of synthesis on an M4 Pro at fp32; a typical 12–15-word sentence does not (550 ms+), and an M1 (4 P-cores) will be roughly 2× slower. The reliable route to the target is independent of the option chosen: synthesise a short first chunk (first clause / ~8 words) and the rest sentence-by-sentence, and default to int8 or fp16. Caveat: published figures say int8 is 2–3× _slower_ than fp32 on Apple CPUs (older ORT); ORT 1.31 here shows the opposite, so the spike must re-measure through the `ort` crate.

### Recommendation

**B2 now, with B3 as a small follow-on stage**: `ort = "=2.0.0-rc.14"` (features `download-binaries`, no `coreml`, `PreferCPU`) + `misaki-rs` with `default-features = false`, adapter in `tts/local.rs`, HTTP backend kept as `TtsBackend::Http`. It is the only option that keeps Mouthy MIT without argument, builds with plain `cargo build`, adds two direct dependencies we pin ourselves, and gives automatic British phonemes from the `b*` voice prefix. A1 is rejected on licence and hygiene; A2 saves nothing over B2 because the Kokoro part is ~150 lines of `ort` calls. B1 is rejected: it carries the licence risk for only OOV words, and B3 recovers the same quality through a subprocess when the user has Homebrew espeak-ng.
**Biggest risk:** OOV handling. Spelling "Kubernetes" or a surname letter-by-letter is jarring; `misaki-rs` was corrected "using eSpeak" (derived data, licence note defers to misaki Apache-2.0) and we have no coverage figure for GB prose. Mitigations in order: B3 subprocess, or swap to `loqui-g2p` (neural fallback, same shape of adapter) if a sample text shows >1 OOV per paragraph.
**1-day spike must prove:** (1) `ort` rc.14 on arm64 runs `model.onnx` and `model_quantized.onnx` with `input_ids`/`style`/`speed` from a raw `bm_lewis.bin` row and matches the Python audio (int8 timing confirmed or refuted); (2) `misaki-rs` `G2P::new(true)` output on 20 real sentences (news, code docs, names) token-maps into Kokoro's vocab with no `❓`, and OOV rate is acceptable; (3) release-binary size delta is ~19 MB and `tauri build` keeps a working bundle.

**Seam pauses — measured** (temporary probe on the real int8 model, `bm_lewis`, debug; silence = |sample| ≤ 0.003, about −50 dBFS; edges move ≤ 25 ms at 0.001, so the padding is clean near-zero):

| Piece (1×)                        | Leading silence | Trailing silence |
| --------------------------------- | --------------- | ---------------- |

| same ending in `.`                | 394 ms          | 591 ms           |

- Kokoro pads every inference by ~0.4 s before and 0.5–0.8 s after (longer pieces get more), **whatever the last punctuation**: a cut at a comma gets no extra pause from the model, just the same padding.
- Its own pauses inside one inference: comma 380 ms, semicolon 405 ms, full stop 470 ms at 1×; 540 / 655 ms at 0.75×, 250 / 305 ms at 1.5×, 190 / 230 ms at 2× (≈ 1/speed). Padding at 1.5×: ~323 ms lead, ~410 ms trail; at 2×: ~330 / ~335 ms.
- Step 11: `split_sentences` gives two chunks (297 + 31 characters; `split_long` cuts at the last space before 300). `split_first_clause` does not cut it (no clause break). The first chunk is 293 ids, so `split_tokens` makes two pieces (144 + 149, cut at a space). Two seams, both mid-phrase: 827 + 405 ≈ 1.23 s and 732 + 400 ≈ 1.13 s of silence. Those were the two pauses.
- **Fix (`tts::local`):** `trim_silence` keeps at most `LEAD_MS` 50 ms before each piece's first sample above `SILENCE` (0.003) and, after its last, `PAUSE_END_MS` 400 ms or `PHRASE_END_MS` 100 ms, both divided by the speed. **Pause rule (from review):** `split_sentences` returns `text::Chunk { text, ends_sentence }`; `ends_sentence` is false only for a `split_long` length cut, and `split_first_clause`'s head is true while its tail keeps the sentence's flag. The last piece of a chunk that ends a sentence (punctuation, a line break such as a heading or bullet, the end of the text, or a first-clause cut) keeps `PAUSE_END_MS` whatever its punctuation, because misaki drops `…`, `—`, quotes and brackets and a line break ends a sentence with none. Every other piece (inside a chunk from `split_tokens`, or the end of a `split_long` cut) keeps `PAUSE_END_MS` only if it ends in a `PAUSE_IDS` token, else `PHRASE_END_MS`. `split_long` stays on the Local path: `LocalSynth::synthesize` returns a chunk's pieces together, so without it a long run-on sentence would wait for every piece before the first audio. The HTTP path ignores the flag. With the next piece's 50 ms lead a pause is ~450 ms, between Kokoro's comma (380) and full stop (470), which the review judged indistinguishable. The first version keyed three tiers off the last token only, so lines without a full stop got a 150 ms breath. Every piece and so every sentence is trimmed, including the first piece's lead-in; the HTTP backend is not touched. All silence gives no samples.

### Stage P3.0 — reflow hard-wrapped text before sentence splitting (2026-10-21) `[feat]`

From the user: text copied from programs that lay out their own lines (Claude Code, nvim, man pages) and from email and PDFs has a newline at every wrapped line, and `split_sentences` ends a sentence at every line break (on purpose, so headings and bullets read as sentences). Each wrapped line got a full pause and its own falling intonation.

**Where:** `text::reflow(&str) -> String` is the first step of `normalize`, before `strip_line_markers` (which would remove the `#`, `-` and `>` it needs). `actions.rs` calls `normalize` once for every request, so Local, HTTP and the HTTP path's plain `normalize` + `split_sentences` output all get it. `split_sentences` is unchanged, so its line-break tests still hold; `normalize` drops the blank lines `reflow` leaves.

**Rules**, in order:

1. CRLF and lone CR become `\n`. A line that is empty or holds only whitespace, box-drawing characters (U+2500–U+257F), `⏺`/`⎿` or a byte order mark is a paragraph break.
2. Fenced code (` ``` ` or `~~~`, also behind `⏺`, `⎿` or a quote gutter) is copied verbatim to its closing fence; one left open inside a quote gets its closing fence written, so a second pass reads it the same way.
3. Two or more consecutive lines sharing a gutter (`│ ┃ ╎ >`, but not `>>>`) lose it, one level at a time (nested `> >` too), and the text inside is split and reflowed again on its own. One quoted line in prose keeps its `>` and is never joined; a line indented to its text, as Claude Code shows a wrapped prompt, continues it.
4. Leading `⏺`/`⎿` and a byte order mark count as indent.
5. A break always stays when the next line starts like structure (heading `#`, `- * •` plus space, `1.`/`2)` plus space, `>`, `$ `, `>>>`, `... `, `|`, box-drawing, a fence); when the line is a heading, prompt, table or box row (a row: a tab between words, `│` or `|`); after a list item or quote unless the next line is indented to its text (its hanging indent); when the indent changes by two or more columns (tabs to multiples of 8), unless the next line sits at the line's hanging column, which is also the word after a 2+ space gap as in man's `-A      Include …`; after `.!?…:;` (closing quotes and brackets, `*`, `_` and backticks allowed after), except after an abbreviation from `ABBREVIATIONS`; after a markdown hard break (two trailing spaces); in a paragraph whose widest line is under 40 columns (`MIN_WRAP_CHARS`); and in a paragraph that is code (a line ending in `{` or `:` followed by a deeper plain line) or chat (two or more lines starting `name:` or `name —`).
6. Otherwise the fit test decides, as greedy wrapping does: a line moves a word down only when it does not fit, and fills every line but a paragraph's last. The break stays when the next line's first word would have fitted on the line (line width + 1 + word ≤ the paragraph's widest line), or when the next line itself left room for the word after it. Widths count columns with the indent.
7. A next line starting in lower case or with a capitalised word (a name, "I") then joins with a space. One whose first word has a digit (a number, a hash such as `a1b2c3d`, a code such as `E0308` or `ABC-123`) or is in capitals of two or more letters (a log level such as `WARN`) joins only when the line or the line after the next starts in lower case, so a git log, compiler errors or a log stays apart. A word with a digit does not count as lower case. (Until P3.1 capitals needed that lower-case neighbour too; the user chose the fit test alone, see Stage P3.1.)
8. A join after a letter and `-` adds no space and keeps the hyphen ("well-known", "Anglo-Saxon"; "neigh-bouring" still reads as two parts, as it did).
9. The text's first line may be the tail of a line the selection began in: when it has no indent and the next line has one, the indent change does not count, and a lower-case next line joins whatever the widths.
10. Kept lines lose their indent and are separated by a blank line, so a second pass finds nothing to join.

**Thresholds:** only `MIN_WRAP_CHARS` (40); the fit test needs none. A first version used two width shares (a line at least 70% of the widest joins, or 50% before a lower-case line); review replaced them with the fit test, which every genuine wrap in the corpus passes (greedy wrapping guarantees it). The fit test alone still joins after a paragraph's widest line, which is why rules 6 and 7 add the next line's own fit and the lower-case neighbour: without them two unmarked headings over a paragraph (48 + 1 + 6 > 54), "Order number: 4821-7734" under a long line, an unmarked list and a web heading over "Install" were joined. Since P3.1 the neighbour applies to numbers and codes only, so the unmarked list and the web heading join (the user's decision). **Rules**, on each whitespace-delimited word:

1. Dotted initials: two or more groups of one letter, or a capital and a small letter ("Ph", "Sc"), each followed by a stop and not by a letter or digit (`U.S.`, `e.g.`, `i.e.`, `a.k.a.`, `Ph.D.`, `U.S.A.-made`), are spelled. Their last stop stays when no letter or digit follows in the chunk, and, for capital initials, before a capitalised word ("in the U.S. Analysts expect"); "e.g." and "i.e." never keep it. An "'s" joins the spelling (`U.S.'s` → `jˌuːˈɛsɪz`); any other apostrophe ending (`ID'd`) leaves the word as written, because misaki reads it as one token and drops an override that covers only the letters.
2. A `.` between letters or digits, unless both are digits, is " dot " (`Node.js`, `file2.txt`, `3.x`, `ort.pyke.io`); one starting a word, or after `( [ { " ' /`, before a letter is "dot " (`.env`, `.NET`). Other stops stay.
3. All capitals, two or more letters, with an optional `s` or `'s`: first `SAID_AS_WORDS`, respelt also in lower case (AJAX, CORS, CUDA, FIXME "fix me", JSON "jason", README "read me", TODO "to do", TOML "tom el", UNIX, YAML "yam el"). Then `INITIALISMS_THAT_SPELL_WORDS` (AD, AM, BA, BI, COO, ER, ETA, ID, IDE, IT, LED, MA, OS, PA, SEC, US) are spelled unless the word next to them across a space is a capitals word the lexicon knows that is not on that list ("DO IT NOW", "LET US KNOW"); "I" or "A" counts only with such a word beyond it ("I AM HERE"), so "the ID I sent", "in the US I learned" and "your US ID card" are spelled. Other capitals the gold lexicon has as written, in lower case or capitalised, stay (NASA, NATO, GIF, RAM, ROM, LAN, WAN, GUI, PIN, SIM, SQL, ASAP, CRUD, MIDI, JPEG; NOTE, MUST). The rest are spelled when they have 2–4 letters or no vowel (`HTTPS`); longer ones with a vowel stay (UNESCO, SIGKILL).
4. Camel case is cut at lower→upper and before the last capital of a run followed by two small letters (`Git Hub`, `mac OS`, `HTML Parser`, `i Phone`, `O Auth`, `Fast API`); rule 3 then runs on each part. The word stays whole when the gold lexicon has it (iOS, YouTube, McDonald, SaaS, LaTeX, IoT: 57 GB / 61 US camel entries), for `Mc` names, and when a part is neither a word the lexicon knows, a single letter nor capitals (`PostgreSQL`, `XMLHttpRequest`, `PyTorch`): espeak-ng reads those whole, and misaki would spell the fragment.
5. Single letters ("a", "I", "B", `3D`, `H2O`) never change.
6. Square brackets reach misaki as parentheses (`plain_text`): it reads `[text](…)` as a pronunciation, so an earlier `[` in the text would pair with an override and swallow the words between ("[TODO: fix the API before release]" read only "API before release"). misaki reads both as a space; `normalize` has already turned markdown links into their text.
