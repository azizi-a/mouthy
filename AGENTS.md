# AGENTS.md

This file provides guidance to AI coding assistants working with code in this repository.

## Development Commands

**Prerequisites:**

- An Apple Silicon Mac on macOS 13.4 or later: ONNX Runtime's prebuilt archive is arm64 only, so Intel and universal builds fail to link
- [Rust](https://rustup.rs/) 1.92 or newer (`ort` rc.14's `rust-version`)
- [Bun](https://bun.sh/) package manager
- Network for the first `cargo build`: `ort-sys` downloads ONNX Runtime (~10 MB) from `cdn.pyke.io` into `~/Library/Caches/ort.pyke.io`
- Kokoro model files come from Settings → Models at run time and are never committed; an OpenAI-compatible TTS server (e.g. Kokoro-FastAPI on `http://127.0.0.1:8880`) is only needed to test the HTTP backend

**Core Development:**

```bash
# Install dependencies
bun install

# Run in development mode
bun run tauri dev

# Build Mouthy.app (skips the DMG, which needs Finder automation)
bun run tauri build --bundles app

# Build frontend only (TypeScript + Vite)
bun run build

# Rust tests
cd src-tauri && cargo test
```

**Linting and Formatting (run before committing):**

```bash
bun run lint                # ESLint for frontend
bun run lint:fix            # ESLint with auto-fix
bun run format              # Prettier + cargo fmt
bun run format:check        # Check formatting without changes
bun run check:translations  # Every locale must match en's keys
```

For platform-specific build setup, see [BUILD.md](BUILD.md).

## Architecture Overview

Mouthy is an offline-first desktop text-to-speech app built with Tauri 2.x (Rust backend + React/TypeScript frontend). It is a fork of Handy with the I/O path inverted: highlight text in any app, press a global hotkey, hear it read aloud; press again to stop.

Speech comes from Kokoro-82M running in-process (`tts_backend = local`, the default: ONNX Runtime via `ort`, phonemes via `misaki-rs`) from model files downloaded into the app-data `models/` folder, or from an external OpenAI-compatible HTTP server (default `http://127.0.0.1:8880`, `POST /v1/audio/speech`, voice `af_alloy`); default hotkey ⌥⎋. Bundle identifier: `com.azizi.mouthy`.

### Backend Structure (src-tauri/src/)

- `lib.rs` - Entry point, Tauri setup, plugin and command registration
- `actions.rs` - `ShortcutAction` trait + `ACTION_MAP` (`SpeakAction` is a thin wrapper); `speak_selection`/`stop_speaking`, the app-managed `TtsState`, the synth thread and the playback thread
- `tts/mod.rs` - `Backend` (chosen per request from settings) and `Synth` (opened on the synth thread)
- `tts/text.rs` - `normalize` (URLs, markdown, whitespace) and `split_sentences` (cuts a sentence longer than `Backend::max_chunk_chars`: 300 for HTTP, 450 for Local); for the local backend only, `split_first_clause` and `expand_numbers` (the HTTP path speaks `normalize` + `split_sentences` output)
- `tts/http.rs` - `synthesize` (PCM s16le mono 24 kHz) and `list_voices` against the HTTP backend
- `tts/local.rs` - in-process Kokoro: model files, the loaded model (`LOADED`), the last preload error (`PRELOAD_ERROR`), text clean-up (`plain_text`), phoneme mapping, one inference per chunk of up to `PIECE_TOKENS` (510, Kokoro's limit) ids
- `tts/espeak.rs` - optional reading of words the lexicon lacks by a user-installed `espeak-ng` (GPL-3), run as a subprocess per word, never linked or bundled
- `tts/catalog.rs` / `tts/download.rs` - the downloadable Kokoro files (URL pinned to one Hugging Face revision, size, sha256) and the resumable, checksum-verified downloader
- `clipboard.rs` - `capture_selection`: snapshot pasteboard, send ⌘C, poll, read, restore
- `input.rs` - Enigo state and layout-aware copy keystroke (main thread only on macOS)
- `audio_out.rs` - Opens the selected output device for rodio playback
- `audio_toolkit/` - Output device listing and the cpal host
- `shortcut/` - Global hotkeys. Two backends: `handy_keys.rs` (default on macOS and Windows; supports fn and modifier-only keys) and `tauri_impl.rs` (fallback, default on Linux); `handler.rs` routes events to `ACTION_MAP`
- `secure_input.rs` - Detects macOS Secure Input, which blocks the handy-keys event tap
- `overlay.rs` - Overlay window (label `overlay`): `speaking`, `nothing-selected`, `error` and `model-missing` states
- `tray.rs` / `tray_i18n.rs` - Tray menu (Speak selection / Stop / Settings / Quit); strings generated by `build.rs` from each locale's `tray` section
- `settings.rs` - Settings struct, defaults, persistence
- `cli.rs` / `signal_handle.rs` - CLI flags and Unix signals
- `autostart.rs` - Launch at login
- `commands/` - Tauri command handlers; `commands/models.rs` lists, downloads, cancels and deletes model files for the Models page

### Frontend Structure (src/)

- `App.tsx` - Main component with onboarding (Accessibility permission)
- `components/settings/` - Settings UI: `general/`, `models/`, `advanced/`, `debug/`, `about/`
- `components/onboarding/`, `ui/`, `icons/`, `footer/`
- `overlay/` - Overlay window entry point and `SpeakingOverlay` UI
- `hooks/useSettings.ts`, `stores/settingsStore.ts` - Settings state (Zustand)
- `bindings.ts` - Generated Tauri type bindings (tauri-specta)

### Key Architecture Patterns

**Speak loop:** hotkey, tray, CLI or signal → `actions::speak_selection` → main thread: if speaking, stop (a hotkey press only once the hotkey was released since the speech started, so a held key's repeats never stop it); else capture selection → normalise → split → synth thread (`block_on` per sentence, bounded channel) → playback thread (sole owner of the rodio `Player`). Every session change runs on the main thread, the only thread that locks `TtsState`, so a press during the capture queues behind it and then stops. A session's stop flag is its identity: a finished playback thread ends only its own session.

**Command-Event Architecture:** Frontend → Backend via Tauri commands; Backend → Frontend via events.

**Settings pattern:** add the field with a serde default to `AppSettings` and `get_default_settings` in `settings.rs`, add a `change_*_setting` command, register it in `lib.rs`, regenerate bindings, and add a `settingUpdaters` entry in `settingsStore.ts`. Unknown stored keys are ignored and a missing or unreadable field takes its serde default, so there are no migrations.

**Bindings:** `src/bindings.ts` is written by tauri-specta when the debug binary starts, not at `cargo build`. Run the debug binary from `src-tauri` (the output path is relative to the working directory) and commit the regenerated file with the change.

**`block_on`:** only on the synth thread. It panics on a Tauri runtime worker, where commands and the single-instance callback run.

**Local backend:**

- One ONNX Runtime `Environment` per process (`tts::local::ENVIRONMENT`, a `OnceLock`, never dropped); a second `ort::init().build()` errors.
- `tts::local::LOADED` is locked only by the synth and preload threads, never the main thread; a session holds it until its synth thread ends, and a stop interrupts the running inference.
- A preload records its outcome in `tts::local::PRELOAD_ERROR`, a separate lock, so the async `list_model_files` can read it while a session holds `LOADED`; then it sends `model-files-changed`. Missing files unload the model.
- A chunk is one inference of up to `PIECE_TOKENS` (510) ids, so its intonation spans the sentence; splitting it gives each piece sentence-final intonation. ONNX Runtime keeps the memory of its longest run (~1 GB at 510 ids), and sessions turn its memory pattern off, without which the arena grows ~40% past that. `tts::local::MAX_CHUNK_CHARS` (450) keeps a chunk of prose within 510 ids; `split_tokens` cuts the rare longer one.
- Sessions use `AutoDevicePolicy::PreferCPU`; rc.14's default routes to CoreML, which is slower here.
- Release builds link ONNX Runtime only because `build.rs` passes `-fapple-link-rtlib` (LTO drops std's weak `___isPlatformVersionAtLeast`).

**Model downloads:** each is a task on the async runtime wrapped in a `futures_util` `Abortable`, writing `<file>.part` until size and sha256 match, then renaming into place. `commands::models::ModelDownloads` is locked briefly, never across an `await`. Catalog URLs are pinned to one Hugging Face revision so the hard-coded hashes stay true.

### Single Instance Architecture

Launching when already running brings the settings window to front. Remote-control flags launch a second instance that forwards its args via `tauri_plugin_single_instance`, then exits. `CliArgs::parse` runs first, so every forwarded flag must be declared in `cli.rs`.

## Internationalization (i18n)

All user-facing strings must use i18next translations. ESLint enforces this (no hardcoded strings in JSX).

**Adding new text:**

1. Add key to `src/i18n/locales/en/translation.json`
2. Add the same key (English value is fine) to every other locale, or `check:translations` fails
3. Use in component: `const { t } = useTranslation(); t('key.path')`

A missing `tray` key renders as a blank menu item.

Locales live in `src/i18n/locales/<lang>/translation.json`; `en` is the source.

## Code Style

**Rust:**

- Run `cargo fmt` and `cargo clippy` before committing
- Handle errors explicitly (avoid unwrap in production)
- Use descriptive names, add doc comments for public APIs

**TypeScript/React:**

- Strict TypeScript, avoid `any` types
- Functional components with hooks
- Tailwind CSS for styling
- Path aliases: `@/` → `./src/`

**Project rules:**

- Ask before adding any dependency not already in the repo.
- Delete, don't disable: remove dead code paths and their dependencies outright.
- Match the existing style; no new frameworks.

## CLI Parameters

**Implementation:** `cli.rs` (definitions), `main.rs` (parsing), `lib.rs` (applying), `signal_handle.rs` (signals); both call `actions::speak_selection` / `actions::stop_speaking`

| Flag                | Description                                                |
| ------------------- | ---------------------------------------------------------- |
| `--speak-selection` | Speak the selection on a running instance, or stop speech  |
| `--stop`            | Stop playback on a running instance                        |
| `--start-hidden`    | Launch without showing the main window (tray icon visible) |
| `--no-tray`         | Launch without system tray (closing window quits the app)  |
| `--debug`           | Enable debug mode with verbose (Trace) logging             |

On macOS, `SIGUSR2` speaks the selection and `SIGUSR1` stops. Linux handles only `SIGUSR2` (WebKitGTK uses `SIGUSR1`).

CLI flags are runtime-only overrides — they do NOT modify persisted settings.

## Debug Mode

Access debug features: `Cmd+Shift+D` (macOS) or `Ctrl+Shift+D` (Windows/Linux)

## Platform Notes

- **macOS** (primary target): Accessibility permission is required to send ⌘C. Under `tauri dev` it is charged to the terminal, not Mouthy. After rebuilding a bundled app, re-grant with `tccutil reset Accessibility com.azizi.mouthy`. The default hotkey ⌥⎋ is also macOS "Speak selection" (Accessibility → Spoken Content).
- **Windows / Linux**: kept compiling where cheap, not actively tested. Linux overlay uses GTK layer shell (disable with `MOUTHY_NO_GTK_LAYER_SHELL=1`).

## Commits

Use conventional commit prefixes (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`). Focus the message on _why_, not _what_. Add a line to `CHANGELOG.md` under the top, unreleased version for user-visible changes.
