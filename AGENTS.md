# AGENTS.md

This file provides guidance to AI coding assistants working with code in this repository.

It describes Mouthy as it stands once Phase 1 of [PLAN.md](PLAN.md) lands. While Phase 1 is in progress, some STT code inherited from Handy is still present; PLAN.md's Current State says which stages are done.

## Development Commands

**Prerequisites:**

- [Rust](https://rustup.rs/) (latest stable)
- [Bun](https://bun.sh/) package manager
- An OpenAI-compatible TTS server for manual testing (e.g. Kokoro-FastAPI on `http://127.0.0.1:8880`)

**Core Development:**

```bash
# Install dependencies
bun install

# Run in development mode
bun run tauri dev

# Build for production
bun run tauri build

# Build frontend only (TypeScript + Vite)
bun run build

# Rust tests
cd src-tauri && cargo test
```

**Linting and Formatting (run before committing):**

```bash
bun run lint                # ESLint for frontend
bun run lint:fix            # ESLint with auto-fix
bun run format              # Prettier + cargo fmt
bun run format:check        # Check formatting without changes
bun run check:translations  # Every locale must match en's keys
```

For platform-specific build setup, see [BUILD.md](BUILD.md).

## Architecture Overview

Mouthy is an offline-first desktop text-to-speech app built with Tauri 2.x (Rust backend + React/TypeScript frontend). It is a fork of Handy with the I/O path inverted: highlight text in any app, press a global hotkey, hear it read aloud; press again to stop.

Phase 1 synthesises through an external OpenAI-compatible HTTP server (default `http://127.0.0.1:8880`, `POST /v1/audio/speech`, voice `bm_lewis`); default hotkey ⌥⎋. Phase 2 moves synthesis in-process. Bundle identifier: `com.azizi.mouthy`.

### Backend Structure (src-tauri/src/)

- `lib.rs` - Entry point, Tauri setup, plugin and command registration
- `actions.rs` - `ShortcutAction` trait + `ACTION_MAP`; `SpeakAction` owns `TtsState`, the synth thread and the playback thread
- `tts/text.rs` - `normalize` (URLs, markdown, whitespace) and `split_sentences`
- `tts/http.rs` - `synthesize` (PCM s16le mono 24 kHz) and `list_voices` against the HTTP backend
- `clipboard.rs` - `capture_selection`: snapshot pasteboard, send ⌘C, poll, read, restore
- `input.rs` - Enigo state and layout-aware copy keystroke (main thread only on macOS)
- `audio_out.rs` - Opens the selected output device for rodio playback
- `shortcut/` - Global hotkeys. Two backends: `handy_keys.rs` (default on macOS and Windows; supports fn and modifier-only keys) and `tauri_impl.rs` (fallback, default on Linux); `handler.rs` routes events to `ACTION_MAP`
- `secure_input.rs` - Detects macOS Secure Input, which blocks the handy-keys event tap
- `overlay.rs` - Overlay window: `speaking`, `nothing-selected` and `error` states
- `tray.rs` / `tray_i18n.rs` - Tray menu (Speak selection / Stop / Settings / Quit); strings generated by `build.rs` from each locale's `tray` section
- `settings.rs` - Settings struct, defaults, persistence
- `cli.rs` / `signal_handle.rs` - CLI flags and Unix signals
- `autostart.rs` - Launch at login
- `commands/` - Tauri command handlers

### Frontend Structure (src/)

- `App.tsx` - Main component with onboarding (Accessibility permission)
- `components/settings/` - Settings UI: `general/`, `advanced/`, `debug/`, `about/`
- `components/onboarding/`, `ui/`, `icons/`, `footer/`
- `overlay/` - Overlay window entry point and UI
- `hooks/useSettings.ts`, `stores/settingsStore.ts` - Settings state (Zustand)
- `bindings.ts` - Generated Tauri type bindings (tauri-specta)

### Key Architecture Patterns

**Speak loop:** hotkey → `SpeakAction::start` → if speaking, stop; else capture selection → normalise → split → synth thread (`block_on` per sentence, bounded channel) → playback thread (sole owner of the rodio `Player`). Each session has a generation number so a stale session never touches the overlay or tray.

**Command-Event Architecture:** Frontend → Backend via Tauri commands; Backend → Frontend via events.

**Settings pattern:** add the field with a serde default to `Settings` and `get_default_settings` in `settings.rs`, add a `change_*_setting` command, register it in `lib.rs`, regenerate bindings, and add a `settingUpdaters` entry in `settingsStore.ts`. Unknown stored keys are ignored, so there are no migrations.

**Bindings:** `src/bindings.ts` is written by tauri-specta when the debug binary starts, not at `cargo build`. Run the debug binary from `src-tauri` (the output path is relative to the working directory) and commit the regenerated file with the change.

**`block_on`:** only on the synth thread. It panics on a Tauri runtime worker, where commands and the single-instance callback run.

### Single Instance Architecture

Launching when already running brings the settings window to front. Remote-control flags launch a second instance that forwards its args via `tauri_plugin_single_instance`, then exits. `CliArgs::parse` runs first, so every forwarded flag must be declared in `cli.rs`.

## Internationalization (i18n)

All user-facing strings must use i18next translations. ESLint enforces this (no hardcoded strings in JSX).

**Adding new text:**

1. Add key to `src/i18n/locales/en/translation.json`
2. Add the same key (English value is fine) to every other locale, or `check:translations` fails
3. Use in component: `const { t } = useTranslation(); t('key.path')`

A missing `tray` key renders as a blank menu item.

Locales live in `src/i18n/locales/<lang>/translation.json`; `en` is the source.

## Code Style

**Rust:**

- Run `cargo fmt` and `cargo clippy` before committing
- Handle errors explicitly (avoid unwrap in production)
- Use descriptive names, add doc comments for public APIs

**TypeScript/React:**

- Strict TypeScript, avoid `any` types
- Functional components with hooks
- Tailwind CSS for styling
- Path aliases: `@/` → `./src/`

**Project rules:**

- Ask before adding any dependency not already in the repo.
- Delete, don't disable: remove dead code paths and their dependencies outright.
- Match the existing style; no new frameworks.

## CLI Parameters

**Implementation:** `cli.rs` (definitions), `main.rs` (parsing), `lib.rs` (applying), `signal_handle.rs` (shared logic)

| Flag                | Description                                                |
| ------------------- | ---------------------------------------------------------- |
| `--speak-selection` | Speak the current selection on a running instance          |
| `--stop`            | Stop playback on a running instance                        |
| `--start-hidden`    | Launch without showing the main window (tray icon visible) |
| `--no-tray`         | Launch without system tray (closing window quits the app)  |
| `--debug`           | Enable debug mode with verbose (Trace) logging             |

On macOS, `SIGUSR2` speaks the selection and `SIGUSR1` stops. Linux handles only `SIGUSR2` (WebKitGTK uses `SIGUSR1`).

CLI flags are runtime-only overrides — they do NOT modify persisted settings.

## Debug Mode

Access debug features: `Cmd+Shift+D` (macOS) or `Ctrl+Shift+D` (Windows/Linux)

## Platform Notes

- **macOS** (primary target): Accessibility permission is required to send ⌘C. Under `tauri dev` it is charged to the terminal, not Mouthy. After rebuilding a bundled app, re-grant with `tccutil reset Accessibility com.azizi.mouthy`. The default hotkey ⌥⎋ is also macOS "Speak selection" (Accessibility → Spoken Content).
- **Windows / Linux**: kept compiling where cheap, not actively tested. Linux overlay uses GTK layer shell (disable with `MOUTHY_NO_GTK_LAYER_SHELL=1`).

## Commits

Use conventional commit prefixes (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`). Focus the message on _why_, not _what_. Add a line to `CHANGELOG.md` under `[Unreleased]` for user-visible changes.
